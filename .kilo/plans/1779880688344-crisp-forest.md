## Plan for Figma Design to Payload CMS and Astro Implementation

This plan outlines the steps to convert the Figma design provided into a functional implementation using Payload CMS and Astro.build.

### Phase 1: Design Token Extraction and Configuration

1.  **Extract Design Tokens**:
    *   Inspect the Figma file ([Figma Link](https://www.figma.com/design/bZPtQN0hU43f7FgPRICCC2/Savior--Copy-?node-id=4809-349&m=dev)) for colors, typography, spacing, radii, and shadows.
    *   Identify breakpoints: 375px, 768px, 1280px, and 1440px+.
2.  **Configure CSS Variables**:
    *   Update `web/src/styles.css` with extracted design tokens as CSS variables within the Tailwind v4 `@theme` block. Ensure naming consistency with Figma.

### Phase 2: Payload CMS Setup

1.  **Component Audit**:
    *   Identify distinct UI pieces in Figma and categorize them as Atoms, Molecules, Section blocks, or Layouts.
    *   Determine which components will be managed by Payload (section blocks) and which will be static.
2.  **Identify Dynamic Content**:
    *   For each section, determine if content needs to be editable by a CMS editor. Mark those as Payload blocks.
3.  **Create Payload Block Schemas**:
    *   Create new schema files in `cms/src/blocks/` for each identified dynamic content section.
4.  **Register Schemas**:
    *   Register the newly created block schemas in the `sections.blocks` array within `cms/src/collections/Pages.ts`.
5.  **Regenerate Types**:
    *   Run `pnpm --filter cms payload generate:types` to update TypeScript types.

### Phase 3: Astro Frontend Implementation

1.  **Scaffold Astro Components**:
    *   Create corresponding Astro component templates in `web/src/components/blocks/` for each Payload block schema.
2.  **Implement Block Routing**:
    *   Update `web/src/components/SectionBlock.astro` to include the new block type and its corresponding Astro component.
3.  **Build Mobile-First Components**:
    *   Implement the UI for each section, starting with the 375px breakpoint.
    *   Apply Tailwind CSS classes for styling, ensuring pixel-perfect accuracy by comparing with Figma.
    *   Incrementally add responsive styles for tablet (768px) and desktop (1280px, 1440px+) breakpoints.
4.  **Wire Content Props**:
    *   Ensure each Astro component accepts dynamic content via props, using sensible defaults.
    *   Use `set:html` or `<RichTextLexical />` for rich text fields.
5.  **Pixel-Accuracy Validation**:
    *   Perform a visual validation loop for each section: screenshot render, compare with Figma, measure discrepancies, and fix.
    *   If Playwright MCP is available, automate screenshot generation.

### Phase 4: Validation and Testing

1.  **Type-Checking and Linting**:
    *   Run `pnpm --filter web run check` to validate workspace file structure and compile correctness.

This plan assumes the Figma Dev Mode MCP is connected and that the Figma URL provided is valid. The asset write directory is not specified, so assets will not be written to disk at this time. Assets will be handled as needed during the implementation phase.
